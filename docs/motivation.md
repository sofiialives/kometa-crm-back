# Мотивация сотрудников

Вкладка «Мотивация» в CRM. Сотрудник видит, сколько денег лежит в его
премиальном банке, какую часть банка он уже заработал баллами и какой у него
уровень работы за месяц. Руководитель ведёт свой отдел, админ — всех и
настройки.

Основа — ТЗ заказчика от 12 октября 2026 и созвон по нему. Где созвон
поменял ТЗ, это отмечено ниже в «Решениях сверх ТЗ».

## Как это устроено

- У каждого сотрудника свой банк на месяц. Первого числа он пуст или равен
  стартовой сумме профиля. Пополняет руководитель (свой отдел) или админ.
- Баллы от 0 до 100. Шкала премии делит банк на уровни: у каждого порог в
  баллах и доля банка. Стартовая шкала: 20/40/60/80/100 баллов и
  15/30/50/75/100 % банка.
- Премия ступенчатая и не суммируется: на третьем уровне человек получает
  сумму третьего уровня, а не всех трёх вместе.
- Шкала уровня работы — оценка месяца словами по тем же баллам, без денег:
  «Разгоняемся», «Хороший темп», «Сильный результат», «Отлично».
- У каждой должности свой профиль: за что баллы дают и за что снимают.
  У события два поля — баллы в премию и баллы в уровень, по умолчанию
  одинаковые.

## Решения сверх ТЗ

Согласованы с заказчиком отдельно. При спорных местах верны они, а не ТЗ.

1. Рост банка. Пополнение идёт только на уровни выше текущего. Уровень, на
   котором человек уже стоит, фиксирует свою сумму в момент выхода на него:
   иначе выгодно сидеть на месте и ждать, пока банк вырастет сам.
   Пункт приёмки ТЗ «при 250 $ третий уровень стоит 125 $» верен, только
   если человек ещё не дошёл до третьего уровня.
2. Защита. Уровень, пройденный при пустом банке, фиксируется первым же
   пополнением — иначе человек прошёл бы его зря.
3. Последний уровень всегда равен всему банку и никогда не фиксируется.
4. Упал ниже уровня из-за штрафов — уровень снова растёт с пополнениями.
   Вернулся — фиксируется заново, по новому банку.
5. Баллы не уходят ниже 0 и выше 100 в любой момент. Штраф при нуле
   сгорает, долга нет: −10, потом +20 дают 20.
6. Списание из банка срезает зафиксированные суммы до «банк × доля»,
   чтобы уровень выше не стоил меньше уровня ниже.
7. Банк и баллы есть только у сотрудников (роль staff). У руководителей и
   админа их нет.
8. Баллы за задачи — и из Иерархии, и личные. Личные идут отдельным
   событием с меньшими баллами и дневным потолком: их человек ставит себе
   сам. Просроченная личная задача штрафуется один раз — потом её удаляет
   ночная уборка CRM.
9. Продление срока самим сотрудником оставлено как есть: это осознанный
   риск, а не недосмотр.
10. Созвоны — ручное событие «Был на созвоне». CRM знает, кого позвали, но
    не знает, кто пришёл.
11. Типов задач в CRM нет, поэтому в каждом профиле одно автособытие «в
    срок». У таргетолога запуск кампании и отчёт объединены.
12. Уведомления до агента — только во вкладке: новое подсвечивается, пока
    сотрудник его не увидел. Сообщения в телеграм будет слать агент. Баллы и
    деньги считает CRM, агент только читает.

Все стартовые цифры — из ТЗ или осторожные значения по умолчанию. Админ
меняет их в «Настройках» без разработчика.

## Хранение

Текущих «баллов» и «банка» в базе нет. Есть два журнала, и всё считается
по ним — так любую цифру можно разложить на записи, из которых она
получилась.

| Таблица | Что хранит |
|---|---|
| MotivationProfile | Профиль должности: название, стартовая сумма, своя шкала, подсказки, дата изменения условий |
| MotivationEventType | События профиля: название, пример, баллы в премию и уровень, ручное или автоматическое, включено ли |
| MotivationPrizeLevel | Уровни шкалы премии. Пустой profileId — общая шкала |
| MotivationWorkLevel | Уровни работы: название, нижняя граница, подсказка |
| MotivationSettings | Лимит штрафа, потолок за личные задачи, уведомления. Одна строка «global» |
| MotivationAssignment | Какой профиль у сотрудника и с какого момента. Не перезаписывается |
| MotivationBankEntry | Журнал банка: стартовая сумма, пополнения, списания |
| MotivationEvent | Журнал событий. Название и баллы копируются при начислении. Отмена вместо удаления |
| MotivationSeen | Когда сотрудник последний раз смотрел вкладку — для подсветки нового |

Месяцы московские: банк и баллы обнуляются в полночь первого числа по Москве
(`src/services/motivation/month.js`).

Расчёт — `src/services/motivation/engine.js`. Модуль без базы: журналы
проигрываются по времени, и на каждом шаге помнится, на какой сумме какой
уровень зафиксировался. Правила 1–6 выше живут там же, с тестами.

## API

Все маршруты под `/api/motivation`, нужна авторизация. Права проверяют и
маршруты, и сервисы.

| Метод и путь | Кто | Что делает |
|---|---|---|
| GET /me?month= | сотрудник | Своя мотивация за месяц |
| GET /me/conditions | сотрудник | «Мои условия» |
| POST /me/seen | сотрудник | Отметить новое как просмотренное |
| GET /team?month=&departmentId= | руководитель, админ | Таблица команды и итоги |
| GET /team/months | руководитель, админ | Месяцы для переключателя |
| GET /employees | руководитель, админ | Кем можно управлять в формах |
| GET /users/:id?month= | руководитель, админ | Мотивация сотрудника |
| GET /users/:id/conditions | руководитель, админ | Условия сотрудника |
| GET /users/:id/options | руководитель, админ | Ручные события его профиля |
| POST /bank/top-up | руководитель, админ | Пополнить банк одному или нескольким |
| POST /bank/write-off | админ | Списание из банка с комментарием |
| POST /events | руководитель, админ | Ручное событие или корректировка |
| POST /events/product | руководитель, админ | Клиент купил новый продукт |
| POST /events/:id/cancel | руководитель, админ | Отменить событие с причиной |
| GET /settings | админ | Всё содержимое «Настроек» |
| PATCH /settings | админ | Лимит штрафа, потолок, уведомления |
| PUT /scale | админ | Общая шкала премии целиком |
| PUT /work-levels | админ | Уровни работы целиком |
| POST /profiles | админ | Новый профиль или копия |
| PATCH /profiles/:id | админ | Название, стартовая сумма, своя шкала, подсказки |
| DELETE /profiles/:id | админ | Удалить никому не назначавшийся профиль |
| PUT /profiles/:id/scale | админ | Своя шкала профиля |
| POST /profiles/:id/events | админ | Новое событие профиля |
| PATCH /event-types/:id | админ | Правка события |
| DELETE /event-types/:id | админ | Удалить событие (кроме покупки продукта) |
| PUT /assignments/:userId | админ | Назначить профиль сотруднику |

Деньги в запросах — в долларах, в ответах — в центах (`…Cents`), как на
доске клиентов.

## Тесты

```
npm test
```

Расчёт и московские месяцы покрыты тестами на `node:test`, без новых
зависимостей: пример из ТЗ, правило роста банка, защита пустого банка,
вершина шкалы, падение уровня, ноль баллов, отмена, списание, своя шкала,
проверки шкалы и уровней.
