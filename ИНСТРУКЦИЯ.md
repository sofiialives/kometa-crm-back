# Что сделано

1. **Локальный админ с доступом к «Мотивации»** — доступ уже есть у любого
   пользователя с ролью `admin` (в `motivation.routes.js` все операции записи
   на вкладке «Мотивация» и так разрешены только `admin`). Отдельный код не
   нужен — нужен только локальный аккаунт, см. шаг 2 ниже.

2. **Тестовый сотрудник с Telegram ID 725100934** — новый скрипт
   `src/scripts/seedTestEmployee.js` создаёт сотрудника и сразу «привязывает»
   к нему этот chatId (без прохода через настоящий `/start <code>` — это
   только для локальных проверок через fakeTelegram.js).

3. **Правка 1 — мгновенная переслылка важного владельцу.** В
   `src/bot/ai/agent.js` убран лимит «не чаще раза в 10 минут» для
   `noteToOwner()`: раньше при повторном важном сообщении от того же
   сотрудника в течение 10 минут бот просто не пересылал его владельцу —
   теперь пересылает сразу. Осталось старое ограничение «не больше 5 в
   день» и «не ночью» — это не то, на что была жалоба, оставлено как защита
   от спама.

4. **Правка 2 — автоштраф «не расставил задачи до 10:00».** Новое
   автоправило мотивации `tasks_not_set`:
   - `prisma/schema.prisma` + миграция — новое значение enum `MotivationAutoRule`;
   - `src/services/motivation/autoTasks.service.js` — функция `chargeTasksNotSet()`:
     в 10:00 по будням проверяет всех активных сотрудников/руководителей,
     у кого нет ни одной задачи со сроком на сегодня, и списывает баллы по
     правилу, если оно включено в профиле (как и остальные автоправила);
   - `src/bot/index.js` — cron `0 10 * * 1-5` (по будням в 10:00 МСК), вызывает
     эту функцию;
   - `src/utils/motivation.js` и `src/components/motivation/ReviewSection.jsx`
     (фронтенд) — подпись правила в выпадающем списке и в очереди «Ждут решения».

   **Важно:** правило штрафует не автоматически для всех — как и остальные
   автоправила, его нужно один раз включить в настройках мотивации
   (вкладка «Мотивация» → условия/профиль → добавить событие с правилом
   «Не расставил задачи на день...» и указать баллы, например −2). После
   этого оно само срабатывает каждый будний день в 10:00 по Москве.

# Как проверить локально

## 1. База и миграции

```bash
cd kometa-crm-back
npm install
# .env: DATABASE_URL=postgres://... (локальный Postgres)
npx prisma migrate dev
npx prisma generate
```

## 2. Локальный админ

```bash
SEED_ADMIN_EMAIL=admin@local.test SEED_ADMIN_PASSWORD=любой_пароль npm run seed:admin
```
Войти в CRM под `admin@local.test` / этим паролем — вкладка «Мотивация»
полностью доступна (баллы, профили, правила, банк).

## 3. Тестовый сотрудник (Telegram ID 725100934)

```bash
npm run seed:test-employee
# по умолчанию: email test.employee@local.test, роль staff, chatId 725100934
# переопределить можно так:
# SEED_EMPLOYEE_EMAIL=... SEED_EMPLOYEE_NAME="Имя" SEED_EMPLOYEE_ROLE=lead SEED_EMPLOYEE_CHAT_ID=... npm run seed:test-employee
```

## 4. Поддельный телеграм (без боевого токена)

В одном терминале:
```bash
node src/scripts/fakeTelegram.js
# слушает http://localhost:4900
```

В другом — запустить backend, направив его на поддельный телеграм:
```bash
TELEGRAM_API_BASE=http://localhost:4900/bot TELEGRAM_BOT_TOKEN=fake npm run dev
```

## 5. Проверка правки 1 (мгновенная переслылка)

Если включён ИИ-агент (`ANTHROPIC_API_KEY` в `.env`), напишите от имени
тестового сотрудника что-то, что агент посчитает важным для владельца,
два раза подряд с разницей меньше 10 минут:

```bash
curl -X POST localhost:4900/_say -H "Content-Type: application/json" \
  -d '{"chatId":"725100934","text":"у меня срочная проблема, нужна помощь владельца"}'

# подождать ответ бота, затем сразу второй раз
curl -X POST localhost:4900/_say -H "Content-Type: application/json" \
  -d '{"chatId":"725100934","text":"ещё одна срочная проблема"}'
```

Посмотреть, что бот отправил (в т.ч. владельцу), через:
```bash
curl localhost:4900/_log
```
До правки второе важное сообщение в тот же 10-минутный интервал владельцу
не пересылалось бы вовсе. После правки — пересылается сразу (если это не
ночные часы и не 6-е важное сообщение за день).

## 6. Проверка правки 2 (штраф за нерасставленные задачи)

1. В CRM (под админом) откройте «Мотивация» → назначьте тестовому
   сотруднику профиль мотивации (если такого ещё нет) и добавьте в него
   событие с автоправилом **«Не расставил задачи на день, проверка в 10:00
   по Москве»**, баллы −2, режим — сразу списывать (или «на проверку», если
   хотите проверить очередь «Ждут решения»).
2. Включите автобаллы по задачам в настройках мотивации, если ещё не
   включены (`autoTasksFrom`/`autoTasksOn` — то же переключение, что уже
   используется другими автоправилами, отдельного включения для
   `tasks_not_set` не требуется).
3. Убедитесь, что у тестового сотрудника **нет** задачи со сроком на
   сегодняшний день (или не ставьте её вовсе).
4. Запустите проверку без ожидания 10:00 — временно вызвав функцию
   напрямую (одноразово, только для теста):
   ```bash
   node -e "
   import('./src/services/motivation/autoTasks.service.js').then(async (m) => {
     const r = await m.chargeTasksNotSet(new Date())
     console.log(r)
     process.exit(0)
   })
   "
   ```
   (Запускать из папки `kometa-crm-back`, backend должен быть настроен на
   ту же базу, что в `.env`.)
5. Откройте «Мотивация» у тестового сотрудника — должно появиться событие
   «Не расставил задачи на день...», −2 балла (или запись в «Ждут решения»,
   если выбран такой режим).
6. Повторный запуск в тот же день **не** должен списать баллы второй раз
   (защита от задвоения — `dedupeKey`).

В реальной работе шаг 4 не нужен — cron в `src/bot/index.js` делает это
сам каждый будний день в 10:00 по Москве.
