# Деплой бэкенда: Render + Render Postgres

## 1. База данных

Render Dashboard → New → PostgreSQL.
- Name: `kometa-crm-db` (совпадает с render.yaml, если используешь blueprint)
- Region: тот же, что у веб-сервиса — иначе внутренний адрес не сработает
- Plan: Free подходит для старта

После создания на странице базы будут два адреса:
- **Internal Database URL** — используй его в `DATABASE_URL`, если бэкенд
  тоже на Render и в том же регионе (быстрее, трафик не выходит наружу)
- **External Database URL** — нужен только если подключаешься не с Render
  (например, локально через `psql` для разовой проверки)

Заливать в саму базу вручную ничего не нужно — таблицы создаст миграция
на шаге сборки (`prisma migrate deploy`), она же превратит пустую базу
в готовую структуру автоматически при первом деплое.

## 2. Веб-сервис

Render Dashboard → New → Web Service → подключить репозиторий бэкенда.

- Runtime: Node
- Build Command: `npm install && npx prisma generate && npx prisma migrate deploy`
- Start Command: `npm start`
- Plan: **Starter** (не Free) — см. предупреждение про сон ниже

Если есть `render.yaml` в корне репозитория — Render предложит развернуть
всё одной кнопкой (Blueprint), включая базу, тогда шаги 1 и 2 объединяются.

## 3. Переменные окружения веб-сервиса

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Internal Database URL из шага 1 |
| `JWT_ACCESS_SECRET` | `openssl rand -hex 32` (свой рандомный) |
| `JWT_REFRESH_SECRET` | `openssl rand -hex 32` (другой рандомный, не тот же) |
| `NODE_ENV` | `production` |
| `CLIENT_URL` | адрес фронтенда на Vercel, без слэша на конце |
| `SEED_ADMIN_EMAIL` | `yan993870@gmail.com` |
| `SEED_ADMIN_PASSWORD` | `admin` |
| `GOOGLE_CLIENT_ID` | из Google Cloud Console, если нужен вход через Google |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | опционально — без них код восстановления пароля просто пишется в лог Render, а не уходит письмом |

С `render.yaml` секреты `JWT_*` сгенерируются сами (`generateValue: true`),
остальное задашь в дашборде при первом деплое (`sync: false` — Render
спросит значение и не будет хранить его в самом yaml-файле).

## 4. Первый админ

После того как деплой прошёл и сервис поднялся, один раз зайди в
Render Dashboard → сервис → вкладка **Shell** и выполни:

```
npm run seed:admin
```

Дальше вход: `yan993870@gmail.com` / `admin`. Смени пароль после
первого входа через «Забыли пароль» либо просто войди и дальше пароль
уже станет постоянным по логике первого входа — трогать повторно
`seed:admin` не нужно, он сам не создаст дубликат, если админ уже есть.

## 5. Важно про бесплатный план

Free-инстанс на Render засыпает после ~15 минут без запросов и
просыпается по следующему запросу (с задержкой 30–50 секунд). Если
сервис спит ровно в полночь — встроенная очистка задач (node-cron
внутри процесса) в этот момент не сработает, выполнится только когда
кто-то откроет CRM в следующий раз.

Для гарантированной работы по расписанию нужен план **Starter** (не
спит вообще) — я его и поставил по умолчанию в `render.yaml`. Если
принципиально важна бесплатность, а не точность полуночной очистки —
можно оставить Free, ничего не сломается критично, просто уборка
задач иногда сдвинется на момент следующего визита в CRM.

## 6. Фронтенд на Vercel

Переменные окружения на стороне Vercel (задаёшь сама):

```
VITE_API_URL=https://<имя-твоего-сервиса>.onrender.com/api
VITE_GOOGLE_CLIENT_ID=<тот же Client ID, что и GOOGLE_CLIENT_ID на бэке>
```

После деплоя фронта — вернись в Render и обнови `CLIENT_URL` на реальный
адрес Vercel (`https://....vercel.app`, без слэша на конце), иначе
CORS будет блокировать все запросы с фронта. Render сам перезапустит
сервис при смене переменной.
